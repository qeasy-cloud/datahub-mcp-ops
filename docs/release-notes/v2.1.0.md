## v2.1.0 — 2026-10-28

**Capability baseline**: `datahub-mcp 0.1.0` / `x-capability-version 2026-10-28` / **58 tools**（55 业务 + 3 meta）

### Highlights

- **静态映射成为一等能力** — 资源中心 → 静态映射资源，两系统对接里的"值翻译表"
  （`1/2/0` → `男/女/未知`、发票类型 → 金蝶编码）现在由 12 个 `mapping.*` 工具完整覆盖
- **`mapping.resolve`** — 用与运行时**完全相同**的语义单值/批量试算，返回 `exact / wildcard / none`
- **`mapping.usage`** — 反查哪些方案字段在用某个映射，并检测"引用了已删分类"的孤儿引用
- **`queue.job.get {rawParams:true}`** — 查看最终报文，排查字段映射不再被折叠成 `__count`
- 平台机制文档新增 §3.7：**映射生效位置不对称**（目标端顶层字段生效；源端仅 object/array 子项生效）

### Added

- 分类：`mapping.category.list` / `get` / `create` / `update` / `delete`
- 对照：`mapping.relation.list` / `create` / `update` / `delete` / `import`（批量 upsert，≤500 行，支持 `dryRun`）
- 判据：`mapping.resolve`、`mapping.usage`
- scope：`mapping:read`（只读档位） / `mapping:write`（standard 以上）
- `docs/`：`references/05` §2.1「映射配了没生效」六步判据；`references/08` C7/C8 反模式

### Changed

- `mapping.category.delete` 在分类仍被方案引用时，**在签发确认令牌之前**直接拒绝（`mapping_category_in_use`），
  需要显式 `force=true` 才会连带删除
- `mapping.*` 的值参数接受数字/布尔（自动转字符串），不再因为 Agent 传 `1` 而校验失败

### Fixed

- `mapping.relation.delete` 把分类集合当成关系集合查询，导致"关系明明存在却报不存在"
- 删除分类的引用预检与令牌流程重复扫描，返回的 `relations_to_remove` 与实际不符时以实际为准

### Verification

  `queue.job.get {rawParams:true}` 的报文里 `FName = 映射后名称`，且不再出现常量 `MAPTEST`
- PHPUnit `--filter Mcp` — 265 passed / 9 skipped
- `scripts/validate_skill.py` — 11 checks
- 回滚验证：`strategy.config.rollback` 恢复目标端配置后 `mapping.usage` 引用归零
