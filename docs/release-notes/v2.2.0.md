**Capability baseline**: `datahub-mcp 0.1.0` / `x-capability-version 2026-11-11` / **58 tools + `strategy.patch`** /
knowledge MCP **4 tools**

> 本版把 Agent 的默认姿势从"从空白/资产开始配、用 create 代替修改"改为
> **先抄在跑方案（REF）→ 再 copy/patch 改 → 有检查点地验证**；
> 同时把团队执行绑定与 13 条用户反馈落成可定位的条款。

---

## Highlights

- **Reference-first**：`knowledge_reference` 组卡 → 质量信号选卡 → `knowledge_fetch` 模板 → 适配 → 落地；
  空结果有分级降级阶梯，不再"0 命中就编案例"。
- **Modify-first**：`strategy.patch`（服务端 capability ≥ `2026-11-11`）按虚拟文档路径修改；
  旧服务端 `update`/`source.update`/`target.update` 等价回退。**不再为改一个字段新建方案。**
- **Four checkpoints**：create 覆盖/脚本丢失核对、字段契约（蓝图字段为上限）、明细行（容器裸名 + 子字段前缀）、
  中文字段说明与时间参数最小集。
- **Script policy**：Agent 只输出代码（事件选择 + `script.validate` 证据 + 保存步骤），SaaS 不再暴露脚本写工具。
- **Team binding**：`docs/team-binding.md` 给出 `dh.py → qeasy_mcp.py` 命令替换、项目上下文与写前四要素；
  `DH_MCP_*` 直连被明确禁止。

## Upgrade notes

- **服务端先升级**：`strategy.patch` 需要 capability ≥ `2026-11-11`；旧服务端继续用 `update`/`source.update`/`target.update`。
- **manifest 重新生成**：`python scripts/dh.py manifest > tools/manifest.json`（服务端发布后执行；本版未手编工具列表）。
- **脚本流程变了**：原先让 Agent `script.create/write` 的用法改为"输出代码由人保存"；
  `strategy.copy` 会复制既有脚本，`strategy.create` 不会（
  见 `references/10-script-patterns.md`）。
- **团队环境**：在线调用改走 `qeasy_mcp.py ... --project <项目>`；`DH_MCP_*` 直连不再被支持。
